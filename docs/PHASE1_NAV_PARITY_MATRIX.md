# Phase 1 — navigation permission parity matrix

Generated by `frontend/scripts/nav-parity-matrix.js` from `frontend/src/app/layout/navigation/nav.registry.ts`.

**Legacy links.** The rule column is the effective condition of the retired `navbar.component.html` (group header `&&` container `&&` link, loose `==`). The unified sidebar evaluates the same expression, so old rule = new rule. `OR` joins the blocks of a route the old navbar listed more than once.

**BMS links.** The retired BMS sidebar showed a link only with the listed ability; the unified sidebar keeps that rule. The retired top navbar additionally listed the same 16 `/bms` routes without any check (the pages were still guarded by `BmsPermissionGuard`); those ungated duplicates are not carried over. This is the only intentional difference, and it only removes links to pages the user could not open.

A group is rendered only when at least one of its links is visible. Evidence: `nav.registry.spec.ts` compares the registry with an independent port of the old template for every combination of 6 departments, 4 positions, 4 roles, 32 module sets and 33 permission sets.
